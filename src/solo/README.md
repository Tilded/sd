# SoloDark V1 and the Western Reaches — Scope and Compatibility

## Executive reading

**SoloDark is an optional solo-play aid for the original Shadowdark rules, not a fourth core rulebook and not a mandatory layer of the Western Reaches expansion.** It gives one person a way to handle the information and judgment normally supplied by a separate Game Master. Its central tools are a yes/no Oracle and a verb+noun Prompt table. Around those tools it adds a small number of Shadowdark-specific solo procedures: group initiative, round-counted light, and a different luck-token economy. (SoloDark, pp. 2–4, 11–14)

The useful distinction is between **the solo procedure** and **the mechanism used to supply uncertainty**. The Oracle and Prompt tables are one published implementation. A tarot draw, another oracle, random tables, or a scripted tool could fill the same broad role. Those alternatives are not rules printed in SoloDark; they are interchangeable implementation proposals.

This review is deliberately limited to material relevant to solo play. It does not re-extract the Western Reaches bestiary, gear, regions, or classes already indexed in the main source bible.

## 1. What SoloDark is

The booklet introduces solo play as a situation in which the player controls the characters and also performs the GM role. It recognizes that the player should not know every answer in advance, so it supplies a way to answer questions a GM would normally settle. (SoloDark, p. 3)

It recommends a group of **2–4 PCs**, says that more than four can become hard to track, and suggests that a single-PC group consider starting at a higher level. It does not prescribe a specific higher level or a scaling formula. Characters are created using standard Shadowdark character creation. Each new PC begins with a luck token under the SoloDark rule called **Fortune's Favor**. (SoloDark, p. 4)

SoloDark is not a replacement combat engine, character system, bestiary, adventure generator, or campaign setting. It points the reader to existing sources for monsters, NPCs, treasure, encounters, dungeons, and wilderness rather than reproducing all of those procedures. It includes a dungeon-name generator, but not a room-by-room dungeon generator. (SoloDark, pp. 6–10)

The source credits Kelsey Dionne for writing, design, and layout and carries a 2023 copyright notice for SoloDark and Shadowdark. The Western Reaches Player's Guide and Game Master's Guide in this repository carry 2026 copyright notices. This establishes the source documents' copyright chronology, not an exact shipping date or a claim about every Kickstarter bonus item. (SoloDark, p. 2; 02, front matter; 03, front matter)

## 2. The portable solo layer: Oracle and Prompts

### 2.1 Use game procedures first

SoloDark says to defer to the game rules before asking the Oracle. If a check, stat block, reaction procedure, encounter table, or other rule already resolves the uncertainty, use it. The Oracle is for a question the rules do not answer. (SoloDark, p. 11)

Ask a reasonable yes/no question, phrase it affirmatively, and ask no more than three Oracle questions in one situation. Do not use it to fish for implausible rewards or outcomes. (SoloDark, p. 11)

### 2.2 Oracle procedure

First decide the odds:

| Odds | Roll state |
|---|---|
| Unlikely or Impossible | Disadvantage |
| Even Chance | Normal roll |
| Likely or Certain | Advantage |

Then roll a d20 and consult the Oracle table: **1–9 = No; 10 = Twist; 11–20 = Yes.** (SoloDark, pp. 11–12)

Interpret the result as follows:

- **Twist (10):** roll a Prompt to discover the unexpected development.
- **Odd result other than a natural 1:** add a “but” turnabout. It complicates the answer without fully negating it.
- **Natural 1 or natural 20:** use the most extreme version of the result.
- **Even result:** use the plain yes/no answer. (SoloDark, p. 12)

The source does not provide a fixed numerical modifier for a “but,” a twist, or an extreme result. These are interpretive instructions, not hidden mechanical bonuses. (SoloDark, p. 12)

### 2.3 Prompts

The Prompts table is a pair of d100 lists: roll a verb and a noun, then interpret the combination in context. It is a source of inspiration for a twist or open-ended uncertainty, not a complete event-resolution system. (SoloDark, pp. 13–14)

### 2.4 Other creative aid

The Dungeon Names tables combine three name components. They help name a dungeon; they do not generate its map, rooms, inhabitants, or balance. The “I Need A…” pages point to possible resources for monsters, NPCs, treasure, encounters, dungeons, and wilderness. Those references do not make the listed outside products required rules dependencies. (SoloDark, pp. 6–10)

## 3. What SoloDark changes in Shadowdark

SoloDark labels these as modified rules. The rest of Shadowdark remains the baseline unless a rule below expressly changes it. (SoloDark, p. 3)

| Area | Shadowdark baseline | SoloDark rule | Classification |
|---|---|---|---|
| Initiative | Individual initiative is established at the beginning of play; a freeform round-robin is also permitted. (01, p. 86) | Choose one PC and one enemy to make initiative checks for their respective groups. The player chooses the order of actions within each group's turn; that order may change each round. (SoloDark, p. 3) | Solo override to initiative only. |
| Chaos Mode | Optional Chaos Mode rerolls initiative at the start of every combat round. (01, p. 114) | SoloDark repeats Chaos Mode and specifies group initiative. (SoloDark, p. 3) | Same option, clarified for group initiative; do not double-reroll. |
| Light | Most light sources last one hour of real time. If real time is not tracked, the core book already says to treat one hour as 10 rounds. (01, pp. 85, 87) | Each light source lasts 10 rounds instead of one hour of real time. (SoloDark, p. 3) | SoloDark makes the core book's 10-round fallback the default. |
| Luck generation | The GM may award luck tokens; each ordinary player can hold one. Spending one rerolls a roll just made, and the new result must be used. (01, p. 82) | A natural 20 grants a luck token. (SoloDark, p. 3) | Adds a repeatable token source. The exact scope of qualifying natural-20 rolls is open. |
| Luck capacity | One token per ordinary player. (01, p. 82) | The solo player may hold as many tokens as there are PCs in the group. (SoloDark, p. 3) | Replaces the ordinary per-player capacity with a party-size capacity. |
| Starting luck | Core character creation does not automatically grant every new PC a starting luck token. (01, pp. 17–18, 82) | Each new PC begins with a luck token. (SoloDark, p. 4) | Solo starting benefit. |
| Luck rerolls | Core luck-token text allows rerolling a roll just made. (01, p. 82) | Tokens cannot reroll out-of-gameplay results; Oracle checks and talent rolls are named examples. (SoloDark, p. 3) | Explicit restriction on what luck can reroll. |

### What it does not change

SoloDark does not replace the core check mechanic, PC action economy, attack rolls, spellcasting checks, HP, conditions, rest, gear slots, morale, reaction rolls, random encounter procedures, treasure XP, or level advancement. Use 01 for those procedures unless a SoloDark rule expressly modifies them. (01, pp. 38–42, 47–53, 82, 84–92, 110, 115–120; SoloDark, p. 3)

The group-initiative rule changes who rolls and how the player orders their side; it does not grant PCs additional actions. The normal one-action-plus-near-movement turn remains in force. (01, pp. 86, 91; SoloDark, p. 3)

A rest remains a ration-backed eight hours of sleep, with the normal interruption and danger procedures. SoloDark does not shorten rest or restore resources automatically. (01, p. 89)

One useful nuance: SoloDark's 10-round light duration is not necessarily a new shorter clock. The core book already provides 10 rounds as the conversion when a table does not track real time. SoloDark simply makes that round-based method explicit for solo play. (01, p. 85; SoloDark, p. 3)

## 4. How it sits beside the later Western Reaches expansion

### 4.1 The expansion does not explicitly adopt SoloDark

The supplied 02 and 03 Markdown sources contain no reference to SoloDark or a solo-roleplaying mode. The occurrences of “solo” in 01/03 refer to a solo monster or a solo duel, not a one-person GM-less campaign. The expansion therefore does not establish that SoloDark is required, superseded, or formally updated. This is a finding about the files currently in this repository, not about Kickstarter PDFs that are not yet available here.

03 says to use the core Shadowdark rules unless it specifies otherwise. It then selects 02's Reaches hex crawl, climate, and downtime procedures, along with the setting's encounter tables and modified boats/mounts. SoloDark can sit beside that structure as an optional GM-replacement layer without displacing the selected Reaches procedures. (03, p. 29)

### 4.2 What remains in force for a solo Reaches campaign

Use the Reaches procedures as written:

- Hex travel, movement by mode and terrain, weather, visibility, food and water, and pushing remain the travel engine. (02, pp. 225–228; 03, pp. 29, 39–41)
- Camping tasks, campfire, ration use, and the normal rest/encounter procedure remain in force. (02, pp. 229–230; 03, pp. 41–43)
- Fast travel, ration calculations, scavenging, and the Drained condition remain in force. (02, pp. 230–231)
- 03's regional encounter tables, Master Hex Key, city-states, factions, rumors, and keyed sites remain the setting content. SoloDark does not replace them. (03, pp. 15–26, 39–83)
- Use the ordinary Shadowdark checks, combat actions, reaction/morale procedures, rest, and advancement underneath the solo layer. (01, pp. 84–92, 110, 115–120)

**Practical order of operations:** published rule or table first; SoloDark Oracle only for a meaningful fact it leaves unresolved; Prompts only when the Oracle produces a twist or the player needs an open-ended spark. This follows SoloDark's instruction to defer to game rules and avoids rolling an Oracle question for something the Reaches procedure already answers. (SoloDark, p. 11; 02, pp. 225–231; 03, pp. 29, 39–64)

### 4.3 The closest expansion counterpart: Seer magic

02 adds **Read the Runes**, a tier 2 Seer spell. The caster asks the Game Master one yes/no question, and the Game Master truthfully answers yes or no. (02, p. 146)

That spell resembles the subject matter of SoloDark's Oracle, but the two are not the same rule:

- **Read the Runes** is a player-character spell, with its own spellcasting cost and a promise of a truthful GM answer. (02, p. 146; 01, pp. 47–50)
- **SoloDark's Oracle** is a meta-game procedure for the solo player to determine uncertain world facts. It assigns odds and can return a twist or “but,” rather than guaranteeing a predetermined truthful answer. (SoloDark, pp. 11–12)

**Solo adaptation proposal:** when a solo Seer casts Read the Runes, first answer from established campaign facts and notes if the truth is already known. If it is genuinely unknown to the solo player, the Oracle could supply the answer. The spell's “truthfully answers” clause and the Oracle's twist/turnabout results are not explicitly reconciled by either source; keep the spell's truth requirement intact and treat any use of a twist as an interpretation decision, not an official combined rule.

### 4.4 The expansion's luck economy is the main mechanical interaction

The Western Reaches books add several ways to create, transfer, restore, enhance, or remove luck tokens. SoloDark's party-size cap therefore matters more in the expansion than in the original core-only game.

| Source option | What it does | Interaction with SoloDark |
|---|---|---|
| Kobold ancestry — Knack | Choose +1 to spellcasting checks or begin each session with a luck token. (02, p. 31) | The session-start token counts against the SoloDark party capacity. |
| Bard — Inspire | Each day grant a number of luck tokens equal to CHA modifier, minimum 1. (02, p. 33) | Token generation remains available; the party cap still applies. |
| Sea Wolf — Freya | Once/day gain a token if the Sea Wolf has none; each use adds 1d6. (02, p. 63) | Retain the feature's “if you don't have one” condition and bonus; also observe the party cap. |
| Seer — Omen | Up to 3/day, make a DC 9 WIS check; success grants a luck token. The Seer cannot have more than one. (02, p. 65) | The Seer's individual one-token limit is stricter than the party cap and remains in force. |
| Seer spell — Fate | A target takes 1d10 damage and loses any luck tokens it has. (02, p. 144) | Can remove a target's tokens; does not change the party cap. |
| Seer spell — Read the Runes | Ask the GM one yes/no question and receive a truthful answer. (02, p. 146) | Oracle is a possible solo implementation for an unknown answer, but not an explicit source rule. |
| Seer spell — Trance | Give a luck token to a touched humanoid other than the caster; target cannot have more than one. (02, p. 147) | Preserve the target-specific cap and the party cap. |
| Camping — Entertain | Grant one luck token to another PC. (02, p. 229; 03, p. 43) | Can generate a token during camping; it does not increase capacity. 02/03 repeat the same task, so do not award it twice. |
| Carousing Benefit | Some outcomes grant a luck token. (02, pp. 237–241) | Apply the SoloDark capacity when the result occurs. |
| Yodeler hex event | Creatures in range regain a token if they spent one that day. (03, p. 89) | A setting-based recovery trigger; track it against the same capacity. |
| Oatali Awakens | Each creature that sees the event gains a luck token and regains 2d6 HP. (03, p. 232) | A setting-based token source; track it against the same capacity. |
| Hard Luck Mode | PCs cannot spend luck tokens on critical failures or effects that generate luck, such as *bless*. (03, p. 29) | Adds a restriction on spending. It does not say that characters cannot gain tokens. |

**Combined reading:** SoloDark supplies the solo party's token capacity and a natural-20 source. The specific 02/03 features remain sources/effects, including their own narrower limits. 03's Hard Luck Mode restricts when tokens may be spent. It does not abolish token generation.

A particularly conservative solo procedure is to track the party's total tokens against the number of PCs, while noting any character-specific restriction such as the Seer's one-token limit. If capacity is full, do not increase it. The source does not say whether an excess token is lost, transferred, or stored for later; this is a practical table ruling, not a printed rule.

## 5. Optional-mode collisions: do not stack unlike packages

The core book already includes optional Modes of Play. SoloDark overlaps with some of them, so use one coherent version of each affected subsystem. (01, p. 114; SoloDark, p. 3)

| Core optional mode | Core effect | Relationship to SoloDark |
|---|---|---|
| Chaos Mode | Reroll initiative at the start of every combat round. (01, p. 114) | Compatible. SoloDark specifies that the initiative rolls are group initiative. Reroll once per side each round. |
| Blitz Mode | Light timers last 30 minutes. (01, p. 114) | Alternative light clock. For SoloDark, use its 10-round timer instead; do not apply both durations. |
| Pulp Mode | No maximum luck tokens; start each session with 1d4 tokens; tokens can also turn hits into critical hits, grant extra actions, or force a GM reroll. (01, p. 114) | Incompatible with SoloDark's party-size cap and its specified luck use. Treat Pulp Mode as a different optional luck package, not an addition to SoloDark. |
| Western Reaches Hard Luck Mode | No spending luck on critical failures or effects that generate luck. (03, p. 29) | Compatible as an added restriction. Apply it alongside SoloDark's ban on rerolling Oracle checks and talent rolls. |

## 6. A limited solo Reaches play loop

1. **Prepare the party.** Use 01 character creation plus any relevant 02 options that 03 makes available in the chosen region. SoloDark recommends 2–4 PCs and grants each new PC a starting luck token. (01, pp. 15–31; 02, pp. 17–71; 03, p. 35; SoloDark, p. 4)
2. **Use the setting procedure.** For travel, camping, climate, rest, and encounter checks, follow 02 as selected by 03. Do not replace scheduled Reaches checks with Oracle questions. (02, pp. 225–231; 03, pp. 29, 39–44)
3. **Play the scene using Shadowdark.** Use ordinary checks and action economy. If combat starts, use SoloDark group initiative; optionally reroll group initiative each round with Chaos Mode. (01, pp. 84, 86, 91; SoloDark, p. 3)
4. **Ask the Oracle only about what remains unknown.** Phrase a reasonable affirmative yes/no question, determine odds, roll, interpret twist/“but”/extreme results, and stay within three questions per situation. (SoloDark, pp. 11–12)
5. **Use Prompts only when interpretation needs help.** The verb+noun pair suggests an unexpected detail; the solo player decides how that detail fits the existing fiction. (SoloDark, pp. 12–14)
6. **Track light and luck.** Use the SoloDark light timer and party-size luck capacity, plus 03's Hard Luck restriction. Keep camping and rest procedures as written, subject to the light/campfire ambiguity below. (SoloDark, pp. 3–4; 01, p. 89; 02, pp. 229–230; 03, pp. 29, 41–43)

## 7. What this suggests for a future scripted solo layer

**Design recommendation, not a source rule:** keep the uncertainty tool behind a replaceable interface. SoloDark's rules can be separated into two modules:

| Module | Input | Output | Replaceable implementation |
|---|---|---|---|
| Ask the Oracle | A clear yes/no question, context, and selected odds | No / Twist / Yes, plus the “but” and extreme-result flags | SoloDark d20 table, tarot draw, another oracle, randomizer, or script |
| Generate a prompt | Current situation or unresolved twist | A verb+noun pair or other interpretive seed | SoloDark d100 tables, tarot spread, random prompt table, or scripted generator |

Keep the following order in any implementation:

**Published game rule/table → Oracle for unresolved facts → Prompt for interpretation → Shadowdark procedure for consequences.**

This preserves the crucial separation between finding out what is true and resolving what the characters do about it. A tarot or script implementation may replace the Oracle's randomizer without changing the game engine. If it also changes group initiative, light, or luck rules, that is a separate mechanical choice.

## 8. Open questions and assumptions

| Question / ambiguity | Working assumption for this review | Reversibility |
|---|---|---|
| Are SoloDark's luck tokens a shared party pool or individually held by each PC? | Treat the number of tokens available to the solo player as capped by party size; record source/owner when a feature has a personal limit. Do not invent a shared-pool rule. | Change to per-PC tracking if a later official clarification specifies ownership. |
| Does every natural 20 generate luck, including Oracle checks and enemy rolls? | The text says “if you roll a natural 20” without defining which rolls count. Treat the broad scope as open; do not use an Oracle natural 20 to generate more Oracle influence unless the campaign adopts that reading. | Narrow or broaden the trigger after a source clarification. |
| What happens when a luck-generating feature triggers at capacity? | No additional token is added; the book does not define overflow, banking, or transfer. | Change if the author or a later supplement specifies overflow. |
| Does the 10-round light duration override the Reaches campfire's specific 8-hour duration? | Keep the explicit 8-hour campfire rule provisionally; apply 10 rounds to ordinary light sources whose core duration is one hour. The sources do not explicitly reconcile these durations. | Apply 10 rounds to campfires too if a later clarification establishes that all light sources are covered. |
| How does a 10-round light timer lose time during an hour/day time skip? | Use the host travel/time procedure for the skip; do not invent a conversion beyond 01's existing time rules. Mark exact rounding as open. | Add a conversion only if a later rule specifies one. |
| Does Oracle answer the Seer's Read the Runes spell? | It may be used as a solo implementation when the truth is unknown, but this is a proposal. The sources do not reconcile the spell's truthful answer with an Oracle twist. | Use established campaign truth or a different truthful-answer procedure instead. |
| Does Hard Luck Mode stop token generation? | No. Its wording restricts spending tokens on specified uses; the listed expansion features can still generate or restore tokens subject to capacity. | Revisit only if a later source expressly prohibits generation. |
| Is SoloDark still the intended solo procedure for the complete Kickstarter package? | Unknown. The current repository contains SoloDark V1 and the two 2026 Western Reaches guides, but not every bonus PDF the user expects to receive. This review does not claim to certify unseen material. | Re-run the compatibility pass when the remaining PDFs are added. |
